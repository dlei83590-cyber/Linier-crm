# 物料管理表单改造 QA（2026-09-27）

> 指令：用户「物料管理改造，基本信息中移除品牌和制造商，类型改为手动输入，移除供应商和采购价关联，计量与状态中移除生命周期和状态，技术属性更改描述为材料属性并移除产品精度等级和预压值，移除采购/销售标记。」
> 范围：apps/web 前端（物料「新建 / 编辑」表单）+ 共享类型输入模块 + docs ｜类型：普通前端改造（FRT-01，无 Schema/Migration ⇒ 不需要 Design/Scope Gate）

## 改造清单（分区前后对照）

| 分区 | 改造前 | 改造后 |
| --- | --- | --- |
| 基本信息 | 编码 / 名称 / 助记码 / 类型(下拉) / 商品来源 / 分类 / 品牌 / 制造商 | 编码 / 名称 / 助记码 / **类型(手动输入 + datalist)** / 商品来源 / 分类 / **描述（迁入）** |

## 类型「手动输入」的实现契约

- `Item.itemType` 是 **DB 枚举**（`ItemType` 10 值）⇒ 本次**不改 Schema**，实现为「文本输入 + 候选」：
  - 共享模块 `apps/web/src/lib/item-type.ts`：`ITEM_TYPE_OPTIONS` / `ITEM_TYPE_LABELS` / `ITEM_TYPE_INPUT_HINT` / `normalizeItemTypeInput(raw)` / `itemTypeLabel(code)`。
  - 归一化接受：枚举码（大小写不敏感）｜中文业务名（如「成品」）。
  - 无法识别 → 前端 `ApiClientError(400, "类型无法识别，请填写：…", "VALIDATION")` 并**阻止提交**；后端 zod 枚举仍为最终权威（400）。
  - 空输入 → 不提交该字段（`itemType` 可选，DB 默认 `FINISHED_GOOD`）。
- 编辑页回填用中文业务名（`itemTypeLabel`），未修改时归一化结果与库中值一致；库中未知值原样展示（不隐藏真实数据）。
- 若将来要「任意新类型」（枚举 → 自由文本/字典表）：属 Schema/Migration + 领域模型变更，**需单独 Design/Scope Gate**。

## 边界（明确没改）

- **零 Schema / Migration / 业务 API / Error Code / Event / 权限码变更**：`POST` / `PATCH /api/items` 的 zod schema 与列全部保留，这些字段仍可经 API 维护。
- **零数据删除**：既有 `brand/manufacturer/lifecycle/status/precisionGrade/preload/isSalable/isPurchasable/isManufacturable` 与 `SupplierItem` 行**一律保留**；编辑页把这些字段从 PATCH payload 移除 ⇒ 不再被覆盖或清空（**不是**显式写 null）。
- 保留上一轮修复：引用源每源独立取数 + 字段级错误可见 + 重试；库存单位 → 采购/销售单位联动；Dirty guard；编码/名称必填；409 CAS 重载。
- 详情页 / 列表页**未改**（见下"待决策"）。

## 第 3 轮：类型=材质分类自动建分类 + 9 字段表单 + 列表重排（2026-09-27「继续优化」）

> 指令：「移除基本信息的商品来源、描述、库存单位、销售单位、和其它，只保留字段顺序：编码、名称、系列、型号、规格、类型、分类、计量单位、OEM编码。类型和系列更改为输入自动保存为分类，类型提示错误（校验错误/类型无法识别…/错误码：VALIDATION）修复。主要用于物料材质分类。重新整理列表字段显示」

### 澄清后的产品决策（已与用户逐项确认）

| 问题 | 决策 |
| --- | --- |
| 「类型」文字存哪里 | **自动匹配/新建「物料分类」(ItemCategory) 并写入 categoryId**；类型本身不再写 `Item.itemType`（零 Schema 变更） |
| 唯一「计量单位」绑定哪列 | **`stockUomId`**（BOM 原料单位红线 / 生产工单行单位 / 换算基准都依赖它）；标签显示「计量单位」 |
| 列表列 | 严格按 9 字段同序（编码/名称/系列/型号/规格/类型/分类/计量单位/OEM编码），去掉 状态/可采购/可销售/创建时间 |

### 实现要点

- 表单：单分区 9 字段；「类型」自由文本（**删除**枚举归一化与「类型无法识别」错误）；「分类」下拉与「类型」**双向联动**；「计量单位」唯一（stockUomId）；移除 助记码/商品来源/描述/采购单位/销售单位。
- 后端：新增可选字段 `categoryName`（POST/PATCH `/api/items`）——命中复用；未命中**同一事务内**新建（level=1 / categoryPath=下一个 3 位数字 / code=MAT-<path>）；新建需 `item-category:create` 否则 403；非空优先于 categoryId；回滚不留孤儿分类；自动新建写审计。
- 并发：分类创建撞唯一约束（P2002）时**重开事务**重试（最多 3 次）——PG 事务内语句失败后即 aborted（25P02），同一事务内无法续查/续写，故重试必须在事务边界（`runWithCategoryConflictRetry`；单测⑨）。
- 列表：9 列同序；「类型」列=分类名、「分类」列=分类树位置（categoryPath + 名称）；筛选「类型」→「分类」；移除 4 列（状态仍可筛选）；列表 API category select 增 `categoryPath`。

### 后果与风险（知情项）

1. 新建物料的 `Item.itemType` 恒为 DB 默认 `FINISHED_GOOD`（表单不再写它）——下游若按 itemType 做科目映射/类型判断，会看到默认值（若要按材质分类驱动这些逻辑，需另立 Design Gate）。
2. 「分类」现在可由「类型」文字**自动新建**：这是新的主数据来源，靠“同名复用（trim + 忽略大小写）”保证不重复；已写审计 `item-category.create`（meta.autoCreatedFromItem=true）。用户若输错字（如「滑块 」多空格已 trim；但「滑快」）会新建一个错误分类——需要在分类管理里清理。
3. 「自动新建」需要 `item-category:create` 权限：只有 item:create 的账号在输入**新**分类名时会被 403 拦住（选择已有分类不受影响）；错误信息已明确提示缺哪个权限。
4. 列表「类型」与「分类」两列同源（一个是分类名、一个是分类树位置）——若希望「类型」列显示 DB 枚举或去掉其一，一行即可调整。
5. 详情页仍展示 品牌/制造商/状态/标记/默认供应商与采购价/精度/预压（只读，数据保留）；是否同步收窄待产品决策。

### 待决策

1. 是否需要「类型」完全自由**新建分类**之外的策略（例如先审核、或只允许在分类管理里建档、或白名单）——当前是即时新建。
2. 系列是否也要参与分类（本轮 系列 仍写入 `Item.series` 文本列，不建分类）。
3. 是否把 `Item.itemType` 的默认值改为按分类/材质推导（需领域决策）。

## 第 5 轮：材料类型 / 分类不一致不再拦截（用户复测反馈，2026-09-27）

> 反馈：实际使用时弹出「校验错误／「材料类型」与「分类」都已填写且不一致，请只保留其中一个／错误码：VALIDATION」，正常保存被挡住。

### 根因

第 4 轮为「不静默覆盖用户显式选择」加了拦截式 400，但两者**最终都写同一个 `categoryId`**，
「都填且不一致」在真实操作里很常见（尤其编辑页两者由详情回填，用户只改分类下拉时材料类型仍是旧名）⇒ 拦截把正常流程堵死。

### 处置

| 项 | 处置 |
| --- | --- |
| 移除拦截 | 删除两页的 400「请只保留其中一个」校验（保存不再被阻断） |
| 判定规则 | **最近修改优先**（`classificationSource`）：后改材料类型 → `categoryName`；后改分类下拉 → `categoryId` |
| 透明提示 | 两者不一致时在对应字段下方显示非拦截提示「保存时以『X』为准」 |
| 不丢输入 | 分类被清空而材料类型仍有文字 → 仍提交 `categoryName` |
| 编辑页复位 | 详情加载 / 409 重载后来源标记复位为「分类」；未再改动即提交 `categoryId`（不改既有分类、不触发按名解析） |

### 验收

| # | 检查项 | 结果 |
| --- | --- | --- |
| X1 | 两者不一致时保存**不再报错**、请求正常发出 | ✅ 单测 |
| X2 | 后改分类 → `categoryId`（无 `categoryName`） | ✅ 单测 |
| X3 | 后改材料类型 → `categoryName`（无 `categoryId`） | ✅ 单测 |
| X4 | 不联动行为不回归（输入不回填下拉、选择不回填输入） | ✅ 单测 |
| X5 | 零后端契约变更 | ✅ |

### 仍待决策（同前）

材料类型目前仍**写进分类**（同名复用/新建），只是 UI 上不联动、不一致时按「最近修改」取舍。
若要材料类型**与分类各自独立保存**（两者并存、互不覆盖），需新增 `Item` 列 + Migration（Schema/领域变更），须单独 Design/Scope Gate。
