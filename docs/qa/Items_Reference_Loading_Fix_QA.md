# 物料管理引用下拉加载失败修复 + 计量单位联动 QA（问题三）

> 日期：2026-09-27 ｜ 指令：用户「物料管理中，分类，库存单位，采购单位，销售单位，以及供应商加载失败修复，关联联动修复」
> 范围：apps/web 前端（物料新建 / 编辑页 + 共享引用选择器）｜类型：普通前端补齐（FRT-01，无 Design/ADR Gate）

## 事实与根因

| # | 现象（用户） | 根因（代码事实） |
| --- | --- | --- |
| 1 | 分类 / 库存单位 / 采购单位 / 销售单位 / 供应商下拉**一起**为空 | 新建 / 编辑页用**单次 `Promise.all`** 拉 4 个引用源；任一源失败即整组 reject → 全部下拉为空（级联，不是 4 个源都坏） |
| 2 | 编辑页连详情都进不去（ErrorPanel） | 引用源与 `GET /api/items/:id` 同一 `Promise.all` → 引用源失败被当成详情失败 |
| 3 | 失败原因不可知、无法恢复 | 新建页只显示「加载分类/计量单位失败」（不说是哪个源、什么状态）；**编辑页完全静默**（无 error prop，下拉空白无提示）；无字段级重试 |
| 4 | 采购 / 销售单位需重复手工选择 | 三处 UOM 无联动（库存单位是计量基准，采购/销售通常一致） |

## 修复内容

| # | 修复 | 位置 |
| --- | --- | --- |
| 1 | 引用源**每源独立取数**（独立 loading / error / reload，AbortController 各自持有；非数组响应视为失败，不静默降级） | `apps/web/src/lib/use-reference-options.ts`（新） |
| 2 | 详情与引用源解耦：详情失败才页面级 ErrorPanel | items/[id]/edit |
| 3 | 失败可见 + 字段级重试：`ReferenceSelector` 增 `onRetry`、失败占位「加载失败，请重试」；共享 `ReferenceErrorNote`（供应商 / 付款条款原生 select 复用）；403 提示缺失权限码，401/密码策略 403/网络/500 各有明确文案 | `components/workspace/reference-selector.tsx` + 两个页面 |
| 4 | 库存单位 → 采购 / 销售单位联动（跟随 / 手工解除 / 改回恢复；编辑页按详情值推导初始态） | items/new + items/[id]/edit |

## 联动语义（必须保持）

1. 选库存单位 → 处于「跟随」状态的采购 / 销售单位同步带出同一单位（含清空）。
2. 用户手工改某字段 → **仅该字段**解除跟随，后续库存单位变更不再覆盖它。
3. 手工改回空值或改回与库存单位一致 → 恢复跟随。
4. 编辑页：详情里采购 / 销售单位与库存单位一致（或均为空）→ 初始跟随；已单独设置 → 不跟随（**不静默覆盖既有数据**）。

## 验证策略

- CI-First：lint → Prisma Client → type-check → unit tests → Build → Secret Scanning 全绿为准（本地不跑高负载验证）。
- 运行时人工验证（部署后）：物料新建页选库存单位 → 采购/销售单位自动跟随 → 手工改采购单位 → 再改库存单位不被覆盖；引用源异常时字段显示真实原因 + 重试可用。

## 残留风险

- 若生产某引用源仍失败（403 / 500），字段会**明确显示缺失权限码或后端 code**——这是本次修复的目标（可见、可执行），但**授权本身不在本次范围**（未放宽 RBAC）；如提示缺 `unit-of-measure:view` 等，需管理员在角色 / 用户附加授权中补齐。
