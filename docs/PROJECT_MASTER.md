# Linier CRM Management System 项目总纲

## 1. 项目基础信息

| 项目项           | 内容                         |
| ---------------- | ---------------------------- |
| 正式英文名称     | Linier CRM Management System |
| 正式中文名称     | 利尼尔 CRM 管理系统          |
| 建设单位         | 福建利尼尔工业装备有限公司   |
| 系统定位         | 公司内部使用的 CRM 管理系统  |
| 唯一业务范围依据 | 合同《系统开发功能清单》     |

本系统服务于福建利尼尔工业装备有限公司内部的客户、销售、订单、财务及经营管理。它不是通用 SaaS CRM。除非获得明确的书面批准，系统不得采用多租户 `workspace`/`tenant` 架构，也不得以未来平台化为由预留或扩展多租户业务能力。

## 2. 范围治理

- 合同《系统开发功能清单》是功能范围、验收边界和变更判断的唯一业务依据。
- 本文仅将合同范围整理为可实施、可测试的业务模块，不替代合同原文。
- 合同未约定的功能不得默认纳入需求，包括但不限于营销自动化、客服工单、机器学习预测、插件市场和通用 SaaS 租户管理。
- 新增、删除或改变合同功能，必须取得项目负责人和合同授权方的书面批准，并同步更新本文件、Sprint 计划及验收依据。
- 技术性支撑能力只能服务于已约定业务，不得演变为新的业务产品范围。

## 3. 角色与权限原则

| 角色           | 权限边界                                                                       |
| -------------- | ------------------------------------------------------------------------------ |
| 系统管理员     | 管理用户、角色、部门、基础配置和操作日志；不因管理员身份自动获得全部业务审批权 |
| 基础资料管理员 | 维护产品、供应商、原料和价目表档案                                             |
| 销售人员       | 管理本人负责或获授权的客户、联系人、商机、跟进、拜访、签到、报价和订单申请     |
| 销售经理       | 查看部门销售数据，分配公海客户，审核业务单据并管理销售过程                     |
| 仓储人员       | 查看获批订单并办理销售出库                                                     |
| 财务人员       | 审核报销及查看获授权的订单、经营数据                                           |
| 公司管理层     | 查看公司经营数据和绩效数据，不直接修改业务原始记录                             |
| 审计人员       | 按授权只读查询操作日志及关联业务记录                                           |

权限必须由“用户—角色—部门—数据范围”共同决定并在服务端校验。部门数据、本人数据和全公司数据的访问范围必须可配置；前端隐藏按钮不能替代权限控制。

## 4. 合同功能模块

### 4.1 基础信息管理

#### 4.1.1 产品档案

- **业务目标：** 统一维护可销售产品的编码、名称、规格、单位、状态及关联资料，为价目、报价、订单和出库提供唯一产品依据。
- **核心流程：** 新建或导入产品 → 校验产品编码 → 完善产品资料 → 启用/停用 → 被价目表及销售单据引用。
- **角色权限：** 基础资料管理员可增删改查和启停；销售人员可查询已启用产品；系统管理员和审计人员按授权审计变更。
- **验收标准：** 产品编码不可重复；必填项校验有效；已停用产品不能新增至销售单据；已被引用的产品不得造成历史单据失真；增删改和启停均生成操作日志。

#### 4.1.2 供应商档案

- **业务目标：** 形成统一、可检索的供应商资料，为原料来源和内部业务查询提供依据。
- **核心流程：** 新建供应商 → 查重与校验 → 维护联系方式及状态 → 关联原料 → 停用或恢复。
- **角色权限：** 基础资料管理员可维护；相关业务人员可按授权查询；审计人员可只读查看变更记录。
- **验收标准：** 供应商名称及约定识别信息可查重；联系人和联系方式可维护；停用后不可用于新增关联；历史关联保留；变更写入操作日志。

#### 4.1.3 原料档案

- **业务目标：** 统一维护原料编码、名称、规格、单位、供应商和状态，支持产品及供应信息查询。
- **核心流程：** 新建原料 → 校验编码 → 关联供应商 → 启用/停用 → 查询或被业务资料引用。
- **角色权限：** 基础资料管理员可维护；相关业务人员可查询；系统管理员和审计人员按授权审计。
- **验收标准：** 原料编码唯一；必填字段、单位和供应商关联校验有效；停用原料不可新增关联；历史数据可追溯；变更生成操作日志。

#### 4.1.4 操作日志

- **业务目标：** 对关键登录、权限和业务数据操作留痕，支持问题定位、责任追溯和内部审计。
- **核心流程：** 用户执行关键操作 → 系统自动记录操作者、时间、对象、动作和结果 → 授权人员检索与查看。
- **角色权限：** 系统自动写入；系统管理员和审计人员只读查询；普通业务人员无权修改或删除日志。
- **验收标准：** 关键新增、修改、删除、审核、状态变更、登录和权限变更均留痕；日志可按时间、人员、模块和动作查询；日志不可经业务界面篡改；敏感凭证不得写入日志。

#### 4.1.5 价目表

- **业务目标：** 统一管理产品基准价格及有效期，为报价和订单价格提供可追溯参考。
- **核心流程：** 创建价目表 → 选择产品并设置价格和有效期 → 提交/生效 → 销售引用 → 到期或停用。
- **角色权限：** 基础资料管理员可编制；销售经理按授权确认或启停；销售人员只读查询生效价目；财务人员可按授权查看。
- **验收标准：** 价格精度、币种和有效期校验正确；同一适用范围的冲突有效期有明确提示；仅生效且未过期价格可默认引用；历史报价保留引用时价格；状态变更留痕。

### 4.2 客户管理

#### 4.2.1 客户档案

- **业务目标：** 建立完整、唯一且可分配负责人的客户主档，集中承载客户基本信息及关联业务。
- **核心流程：** 新建/导入客户 → 查重 → 分配负责人和部门 → 持续维护 → 转入公海或重新分配。
- **角色权限：** 销售人员维护权限范围内客户；销售经理查看和分配部门客户；系统管理员维护基础权限；管理层按授权只读。
- **验收标准：** 必填项和客户查重规则有效；数据访问符合本人/部门/公司范围；客户可关联联系人、商机、跟进、拜访、报价和订单；负责人变化可追溯；未授权用户不能访问。

#### 4.2.2 联系人管理

- **业务目标：** 维护客户相关联系人的身份、职务和联系方式，为销售沟通提供准确入口。
- **核心流程：** 在客户下新增联系人 → 校验联系方式 → 标记主要联系人 → 更新或停用。
- **角色权限：** 客户负责人及获授权销售人员可维护；销售经理可管理部门范围；其他角色按客户权限只读。
- **验收标准：** 联系人必须归属客户；联系方式格式校验有效；同一客户的主要联系人规则明确；停用不删除历史业务关联；访问范围继承客户权限。

#### 4.2.3 客户公海

- **业务目标：** 集中管理暂无负责人或符合回收规则的客户，实现可控领取、分配和回收。
- **核心流程：** 客户进入公海 → 授权人员筛选 → 领取或经理分配 → 成为私有客户 → 按规则退回公海。
- **角色权限：** 销售人员可查看和领取授权公海；销售经理可分配、回收并查看部门记录；管理员配置权限，不直接改变业务归属。
- **验收标准：** 公海进入、领取、分配和退回均校验权限并留痕；并发领取只能有一个成功结果；领取后负责人和数据范围立即生效；历史负责人和操作时间可追溯。

#### 4.2.4 客户查重

- **业务目标：** 在客户创建和导入前识别潜在重复记录，降低一客多档和归属冲突。
- **核心流程：** 输入客户识别信息 → 按合同确认的字段与规则匹配 → 展示候选重复项 → 有权限人员确认新建或处理重复。
- **角色权限：** 销售人员可对录入内容查重并查看权限范围内结果；销售经理可处理归属冲突；管理员维护经批准的查重规则。
- **验收标准：** 新建与导入均触发相同查重规则；匹配结果说明命中依据；无权查看的客户不得泄露敏感详情；强制继续或合并处理须经授权并留痕。

### 4.3 销售管理

#### 4.3.1 商机管理

- **业务目标：** 跟踪潜在销售机会的客户、负责人、阶段、预计金额和预计成交信息。
- **核心流程：** 从客户创建商机 → 指定负责人 → 更新阶段及关键信息 → 赢单或输单关闭。
- **角色权限：** 销售人员维护本人商机；销售经理管理部门商机和阶段；管理层按授权查看；其他角色按业务需要只读。
- **验收标准：** 商机必须关联客户和负责人；阶段流转遵循配置规则；金额和预计日期校验有效；赢单/输单需记录结果；全过程可查询并留痕。

#### 4.3.2 客户跟进

- **业务目标：** 持续记录与客户的沟通内容、结果和下一步安排，形成完整跟进历史。
- **核心流程：** 选择客户/商机 → 记录跟进方式、内容和时间 → 填写结果与下次计划 → 查询时间线。
- **角色权限：** 销售人员维护权限范围内跟进；销售经理查看部门跟进；管理层按授权汇总查看。
- **验收标准：** 跟进必须关联客户，可选关联商机；必填内容和时间校验有效；按时间顺序可查询；修改和删除受限且留痕；无客户权限者不能访问。

#### 4.3.3 拜访计划

- **业务目标：** 规划客户拜访的时间、地点、人员和目的，并跟踪计划执行状态。
- **核心流程：** 创建拜访计划 → 提交或确认 → 到期执行签到 → 填写结果 → 完成或取消。
- **角色权限：** 销售人员创建和维护本人计划；销售经理查看部门计划并按约定确认；参与人员查看相关计划。
- **验收标准：** 计划必须关联客户、负责人和计划时间；状态转换受控；完成时可关联签到及跟进结果；取消需记录原因；超期与执行状态可筛选。

#### 4.3.4 签到管理

- **业务目标：** 记录销售拜访的实际签到时间、位置和关联计划，支持拜访执行核验。
- **核心流程：** 打开待执行拜访 → 获取并确认签到信息 → 提交签到 → 系统记录结果 → 经理查询。
- **角色权限：** 销售人员提交本人签到；销售经理查看部门签到；管理员仅处理权限和技术配置；管理层按授权查看汇总。
- **验收标准：** 签到记录包含人员、时间、位置及关联客户/计划；服务端记录提交时间；重复或异常签到有明确处理；记录不可由普通用户删除；查看符合数据权限。

#### 4.3.5 报价管理

- **业务目标：** 基于客户、产品和价目表形成可审批、可追溯的销售报价。
- **核心流程：** 创建报价 → 选择客户及产品 → 引用或调整价格 → 提交审核 → 批准/驳回 → 形成有效报价版本。
- **角色权限：** 销售人员编制本人报价；销售经理按授权审核价格和条款；财务人员按授权查看；客户相关角色仅访问权限范围内报价。
- **验收标准：** 报价编号唯一；产品、数量、单价、金额和币种计算正确；价目来源及调整可追溯；审核前后编辑权限受控；每次正式变更保留版本和日志。

### 4.4 订单管理

#### 4.4.1 订单申请

- **业务目标：** 将已确认销售需求转为结构化订单申请，并完成必要审核。
- **核心流程：** 基于客户/报价创建申请 → 核对产品、价格及交付信息 → 提交 → 审核通过或驳回 → 进入订单阶段管理。
- **角色权限：** 销售人员创建和提交本人申请；销售经理审核业务内容；财务和仓储按授权查看所需字段；管理员不代替业务审核。
- **验收标准：** 订单申请编号唯一；客户、产品、数量、价格及交付信息校验有效；审核状态和意见完整；未批准申请不得进入出库；关键变更和审核留痕。

#### 4.4.2 订单阶段管理

- **业务目标：** 按合同约定阶段跟踪已批准订单的执行进度、责任和异常情况。
- **核心流程：** 订单获批 → 初始化阶段 → 按规则推进阶段 → 记录时间和说明 → 完成或终止。
- **角色权限：** 销售人员查看并更新获授权阶段；销售经理监督和处理异常；仓储人员更新与出库相关状态；管理层只读查看。
- **验收标准：** 阶段顺序和可执行角色受控；每次流转记录操作者、时间和说明；不允许非法跳转；终止需原因；当前阶段与完整历史均可查询。

#### 4.4.3 销售出库

- **业务目标：** 根据已批准且满足阶段条件的订单登记销售出库结果，实现订单与出库记录关联。
- **核心流程：** 选择可出库订单 → 核对产品和数量 → 创建出库记录 → 确认出库 → 回写订单执行状态。
- **角色权限：** 仓储人员创建和确认出库；销售人员查看本人订单出库；销售经理和财务人员按授权查看；其他角色无确认权限。
- **验收标准：** 仅合格订单可出库；出库数量必须为正且不得违反订单数量约束；支持合同允许的分次出库时须准确累计；确认后关键字段不可随意修改；订单状态同步且操作留痕。

### 4.5 财务管理

#### 4.5.1 报销申请

- **业务目标：** 规范内部业务费用的申请、审核和状态查询，保留完整审批依据。
- **核心流程：** 申请人填写费用明细 → 上传合同要求的凭证 → 提交 → 审核批准或驳回 → 完成处理。
- **角色权限：** 员工创建和查看本人申请；部门负责人按权限审核；财务人员复核并处理；管理层按授权查看汇总。
- **验收标准：** 申请编号唯一；费用类型、金额、日期和凭证按规则校验；审批人不能越权；驳回有原因；状态、意见、金额变更及处理过程可追溯。

### 4.6 数据洞察

#### 4.6.1 经营数据

- **业务目标：** 基于系统内合同范围业务数据提供经营情况查询，为管理决策提供一致口径。
- **核心流程：** 按授权选择时间和组织范围 → 系统汇总订单、销售等既有数据 → 展示明细与指标 → 按合同约定方式导出。
- **角色权限：** 公司管理层查看公司范围；销售经理查看部门范围；财务人员查看授权财务口径；普通员工仅查看获授权数据。
- **验收标准：** 指标定义和数据来源可追溯；筛选、汇总与明细结果一致；数据权限适用于页面和导出；同条件查询结果稳定；不引入合同外预测指标。

#### 4.6.2 绩效数据

- **业务目标：** 基于合同约定的业务事实展示人员或部门绩效，支持内部管理复盘。
- **核心流程：** 选择周期和组织范围 → 按已确认口径计算 → 展示人员/部门结果及来源明细 → 授权查看或导出。
- **角色权限：** 公司管理层查看授权范围；销售经理查看部门绩效；员工查看本人数据；系统管理员不因技术角色获得绩效数据权限。
- **验收标准：** 计算口径经业务方确认；结果可追溯到系统原始记录；组织和人员变动按确认规则处理；本人、部门和公司数据严格隔离；不包含机器学习预测。

## 5. 跨模块验收基线

- 所有模块必须满足 `ACCEPTANCE_STANDARD.md`，并以合同功能条目和已确认原型/需求说明作为场景验收输入。
- 所有关键数据必须实施服务端角色和部门数据权限校验。
- 所有新增、修改、删除、审核和关键状态变化必须按操作日志标准留痕。
- 金额、数量、日期、状态和编号必须具备明确校验规则，列表必须支持合同要求的查询条件。
