# ADR-0006: Menu Center（Sprint 3B）

- 状态：已接受
- 日期：2026-08-05
- 决策者：CIO + CTO 审核
- 分支：feature/sprint3-platform-capabilities

## 背景

前端需要统一的菜单来源。若各页面自行维护导航，会导致：
菜单与权限脱节、排序/隐藏/外链无法统一管理、重复实现。

## 决策

### 1. 两级模型：MenuGroup（分组）+ Menu（树形）

- `MenuGroup`：顶级分组（如 DASHBOARD / MASTER_DATA / PROJECT / WORKFLOW / SYSTEM），
  code 唯一、icon、sort。
- `Menu`：菜单项，`groupId` 归属分组，`parentId` 自关联形成树（父子层级无限）。
- RouteMeta 全部内联在 Menu 上，不单独建表：
  `path / icon / sort / hidden（隐藏）/ cache（缓存）/ externalLink（外链）/ permission（权限码）`。

### 2. 权限关联

- 每个 Menu 可关联一个权限码（如 `workflow-definition:view`），前端按当前用户权限渲染菜单。
- 权限码沿用 `{module}:{action}` 动作级体系（ARCHITECTURE_BASELINE §3），不另建 MenuPermission 表
  （一个菜单对应一个访问权限足够，避免过度建模）。
- 新增模块：`menu`（菜单项）、`menu-group`（菜单组），各 10 个动作级权限；MANAGER 全量。

### 3. API

- `GET /api/menus`：分页列表，或 `?tree=true` 返回树形（前端直接读取）。
- `POST /api/menus`：创建（校验 group/parent 存在、code 唯一）。
- `GET /api/menus/:id` / `PATCH`（乐观锁 version）/ `DELETE`（软删除，递归删除子树）。
- `GET /api/menu-groups` / `POST` / `GET :id` / `PATCH` / `DELETE`（软删除，组下菜单级联隐藏）。
- 统一响应/错误、Zod 校验、后端权限、AuditLog（requestMeta 完整审计）、软删除、transaction。

### 4. 删除策略

- Menu → MenuGroup：Cascade（组删菜单删，逻辑上软删）。
- Menu → Menu（parentId）：SetNull（父删子提升为根，不丢子树）。
- 业务上 DELETE 一律软删除（deletedAt），禁止物理删除（CTO 规则）。

### 5. Seed

- 预置 5 个菜单组 + 11 个菜单（覆盖 Dashboard/主数据/项目/工作流/系统设置/审计），
  稳定 code + upsert，幂等可重复执行。

## 备选方案及放弃原因

- **Menu 直接挂字符串权限数组（Json）**：失去权限码可查询性 → 放弃，用单值 permission 字段。
- **单独 MenuPermission 关联表**：当前一个菜单一个访问权限足够，过度建模 → 放弃，
  待"角色可配置菜单树"需求出现时再升级为关联表（新增 ADR）。
- **前端硬编码导航**：与权限/排序脱节 → 放弃，全部走 API。

## 影响

- 新增迁移 `0006_menu_center`（MenuGroup + Menu 两表 + 索引 + 外键）。
- 新增 2 模块权限（menu / menu-group）；MANAGER 全量授权。
- 前端导航统一从 `GET /api/menus?tree=true` 读取，按 permission 过滤。

## 对后续 Sprint 的影响

- Sprint 4+ 业务模块页面只需新增 Menu 记录（path/permission），无需改前端导航框架。
- File Center / Dashboard 页面同样通过 Menu 挂载。
