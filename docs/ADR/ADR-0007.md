# ADR-0007: Dashboard API（Sprint 3B）

- 状态：已接受
- 日期：2026-08-05
- 决策者：CIO + CTO 审核
- 分支：feature/sprint3-platform-capabilities

## 背景

Dashboard 页面（Sprint 8 BI 阶段）需要组件/布局/指标/图表的数据定义。
若各页面自行硬编码，会导致组件无法复用、指标口径不统一、布局无法配置。

## 决策

### 1. 四个数据模型，只提供数据 API，不写页面

| 模型 | 职责 | 关键字段 |
| --- | --- | --- |
| DashboardWidget | 组件定义（KPI/CHART/TABLE） | code/name/widgetType/dataSource/query/refreshInterval/sort/enabled |
| DashboardLayout | 布局（widget 位置网格） | code/name/isDefault/grid（[{widgetId,x,y,w,h}]）/enabled |
| DashboardKpi | 指标定义 | code/name/unit/aggregate（SUM/AVG/COUNT/MIN/MAX）/dataSource/query/target |
| DashboardChart | 图表定义 | code/name/chartType（LINE/BAR/PIE/AREA/SCATTER）/dataSource/query/xAxis/yAxis |

- 页面（Sprint 8）直接读取这些 API 渲染，本轮不开发任何页面代码。
- `query` 为 Json 查询配置（数据源过滤/统计），`dataSource` 标识业务源（project/sales-order 等）。

### 2. API 设计

- `GET/POST /api/dashboard/widgets`、`GET/PATCH/DELETE /api/dashboard/widgets/:id`（layouts/kpis/charts 同构）
- 列表分页（page/pageSize）+ code/name/enabled 过滤；更新乐观锁 version；删除软删除
- 统一响应/错误、Zod 校验、后端权限、AuditLog（requestMeta 完整审计）

### 3. 权限

- 新增 4 模块：dashboard-widget / dashboard-layout / dashboard-kpi / dashboard-chart，各 10 动作级权限
- MANAGER 全量授权；SUPER_ADMIN/ADMIN 继承

### 4. 迁移策略

- 新迁移 `0007_dashboard_api`：4 表 + 3 枚举（DashboardWidgetType/DashboardChartType/DashboardAggregate）+ 唯一索引（code）
- 仅新增表，不修改既有表（CTO 规则）

## 备选方案及放弃原因

- **KPI/Chart 合并进 Widget**：KPI 有独立口径（aggregate/target），Chart 有独立配置（chartType/坐标轴），合并会导致字段过度膨胀 → 放弃，拆 4 表。
- **页面先行**：无数据定义支撑的页面无法验收 → 放弃，先 API 后页面。

## 影响

- 新增 4 模型 + 3 枚举 + 迁移 0007；新增 4 模块权限
- Sprint 8 BI 页面直接消费这些 API

## 对后续 Sprint 的影响

- 指标口径（KPI aggregate/dataSource/query）集中管理，业务模块只需在数据源上产出数据
- Dashboard 组件可跨模块复用（Widget 定义独立于具体业务表）
