# ADR-0009: Customer Foundation（Sprint 3C-1）

- 状态：已接受
- 日期：2026-08-05
- 决策者：CIO + CTO 审核
- 分支：feature/sprint3-business-foundation

## 背景

Sprint 3C 定义为 Business Foundation（业务底座，非仅 CRUD）：Validation / Permission / Audit / Workflow / Attachment 一起交付。
3C-1 第一个子阶段为 Customer Foundation，需要结构化客户域模型，为后续 Sales/Quote 提供客户主档。

## 决策

### 1. 七模型：Customer / Contact / Address / Tag / Industry / Credit（+ CustomerTag 关联）

| 模型 | 职责 | 关键字段 |
| --- | --- | --- |
| Customer | 客户主档 | code（唯一）/name/shortName/partnerId（关联 BusinessPartner，SetNull）/level（VIP/KEY/REGULAR/PROSPECT）/industryId/region/sourceChannel/companySize/foundedDate/website |
| CustomerContact | 联系人（多） | customerId（Cascade）/name/title/department/phone/email/wechat/isPrimary/sort |
| CustomerAddress | 地址（多） | customerId（Cascade）/addressType（REGISTERED/SHIPPING/INVOICING/CONTACT）/recipient/phone/province/city/district/detail/isDefault/sort |
| Tag | 标签字典（全局复用） | code（唯一）/name/color/sort/enabled |
| CustomerTag | 客户-标签关联 | customerId+tagId 唯一，多对多 |
| Industry | 行业字典 | code（唯一）/name/sort/enabled |
| CustomerCredit | 客户信用（1:1） | customerId 唯一/creditLimit/usedCredit/rating（AAA~C）/status（NORMAL/WATCH/FROZEN/CLOSED）/reviewDate |

- `Customer.partnerId` 关联统一往来单位 BusinessPartner（type=CUSTOMER/BOTH），可选——允许独立建档。
- 删除策略：Customer→Contact/Address/Credit/Tag Cascade（逻辑软删）；Customer→BusinessPartner SetNull；Customer→Industry SetNull。

### 2. 枚举集中管理

- CustomerLevel / CustomerCreditRating / CustomerCreditStatus / CustomerAddressType 四枚举入 schema。

### 3. API 设计

- `GET/POST /api/customers`、`GET/PATCH/DELETE /api/customers/:id`（详情含子资源）
- 子资源：`/api/customers/:id/contacts`（+ `/:contactId`）、`/addresses`（+ `/:addressId`）、`/tags`（+ `/:tagId`）、`/credit`
- 字典：`/api/industries`（CRUD）、`/api/tags`（CRUD）
- isPrimary/isDefault 唯一性：事务内清除其他主联系人/默认地址
- 统一：分页/过滤/排序（API_GUIDELINES）、乐观锁、软删除、AuditLog（requestMeta 完整审计）、Zod、权限、transaction

### 4. 权限

- 新增 7 模块：customer / customer-contact / customer-address / customer-tag / customer-credit / industry / tag，各 10 动作级权限；MANAGER 全量

### 5. 迁移策略

- 新迁移 `0009_customer_foundation`：7 表 + 4 枚举 + 索引 + 外键，仅新增不修改既有表（CTO 规则）

### 6. 事件与错误码

- 事件：`CustomerCreated`（EVENTS.md 已注册）
- 错误码：CUSTOMER_xxx 域（ERROR_CODES.md 已注册基线，本阶段代码使用 ERROR_CODES 常量）

## 备选方案及放弃原因

- **直接在 BusinessPartner 上扩展客户字段**：BP 已是统一往来单位（含供应商），再叠加客户结构会膨胀且与 Supplier 混淆 → 放弃，独立 Customer 主档 + 可选 partnerId 关联。
- **Contact/Address 用 Json 内联**：无法查询/校验/审计 → 放弃，独立子表。
- **Tag 用字符串数组**：无法统一颜色/排序/复用（供应商/物料后续也用）→ 放弃，独立 Tag 表 + 关联表。

## 影响

- 新增 7 模型 + 4 枚举 + 迁移 0009；新增 7 模块权限；seed 预置 6 行业 + 4 标签
- Sprint 4 Sales（Quotation/SO）直接引用 Customer

## 对后续 Sprint 的影响

- 3C-2 Supplier Foundation 复用 Tag 表（供应商标签同源）
- 3C-3 Item / 3C-5 Price 的 Attachment 复用 File Center（3B）
- 信用额度（CustomerCredit.usedCredit）由 Sales 回写（Sprint 4）
