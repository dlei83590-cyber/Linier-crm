# ADR-0010：Supplier Foundation（BusinessPartner 唯一主体 + Partner 级共享）

- 状态：Accepted（Sprint 3C-2）
- 日期：2026-08-06
- 关联：ADR-0009（Customer Foundation）、ADR-0011（BusinessPartner Consolidation）、ARCHITECTURE_BASELINE v1.0

## 背景

Sprint 3C-1 交付了 Customer Foundation（Customer.partnerId → BusinessPartner + CustomerContact/CustomerAddress/CustomerTag/CustomerCredit 子模型）。
3C-2 Supplier Foundation 若照抄 Customer 建一套 SupplierContact/SupplierAddress/SupplierTag/SupplierBankAccount，
将形成两套联系人/地址/标签/银行模型，Sprint 4 销售、Sprint 5 采购必然重构。

## 决策

### 1. BusinessPartner 为唯一主体，角色化扩展
- 新增 `BusinessPartnerRole`（partnerId + roleType，`@@unique([partnerId, roleType])`），
  `PartnerRoleType` 枚举：CUSTOMER / SUPPLIER / BOTH / LOGISTICS / OUTSOURCING，**可无限扩展**。
- 一个企业可以同时是 Supplier 与 Customer（例如 ABB / Siemens / Bosch 既采购又销售），通过多条 Role 表达，而非继承。

### 2. 联系人 / 地址 / 标签 / 银行 / 信用统一为 Partner 级共享
- `PartnerContact` / `PartnerAddress` / `PartnerTag` / `PartnerBankAccount` / `PartnerCredit` 全部挂在 `BusinessPartner` 下（partnerId FK）。
- Customer 与 Supplier **复用同一套**共享表，绝不各自建表。
- `PartnerAddressType` 枚举扩展：REGISTERED / BILLING / SHIPPING / WAREHOUSE / FACTORY / INVOICING / CONTACT。

### 3. Supplier 特有子模型仅三项
- `SupplierQualification`（资质）/ `SupplierCertificate`（证书）/ `SupplierSettlement`（结算条款），挂在 `Supplier` 下（onDelete: Cascade）。
- 供应商企业字段（code/name/uscc/银行/结算/标签等）全部走 BusinessPartner，`Supplier.partnerId` 必填且唯一，校验 BP type ∈ {SUPPLIER, BOTH}。

### 4. Customer 不返工（本次不迁移）
- 3C-1 已交付的 CustomerContact/CustomerAddress/CustomerTag/CustomerCredit **保留兼容**。
- 统一迁移到 Partner 级共享模型列入 Sprint 5 架构优化（见 ADR-0011），避免打断当前开发节奏。

### 5. 附件统一走 File Center
- Qualification/Certificate 的 `attachment` 字段存 FileId（File Center FileAttachment businessType=supplier-qualification / supplier-certificate）。

### 6. Supplier 创建自动写入角色
- POST /api/suppliers 在事务内 upsert `BusinessPartnerRole(SUPPLIER)`（幂等），保证角色与供应商一致。

## 影响

- Schema：+10 模型（BusinessPartnerRole/PartnerContact/PartnerAddress/PartnerTag/PartnerBankAccount/PartnerCredit/Supplier/SupplierQualification/SupplierCertificate/SupplierSettlement）+ 4 枚举（PartnerRoleType/SupplierStatus/QualificationType/PartnerAddressType）→ 总计 79 模型 / 37 枚举。
- 迁移：`0010_supplier_foundation`（10 表 + 4 枚举 + 索引 + 外键，仅新增不改既有）。
- RBAC：+10 模块（supplier/supplier-qualification/supplier-certificate/supplier-settlement/business-partner-role/partner-contact/partner-address/partner-tag/partner-bank-account/partner-credit）。
- API：suppliers 主档 5 + 四类子资源 16 + 共享资源视图 11 + partner roles 3 = 32 端点。
- 前端/集成：Partner 级共享资源通过 `/api/suppliers/:id/contacts|addresses|tags|bank-accounts|credit` 视图读写共享表。

## 权衡

- 采纳 Partner 级共享 vs 独立 Supplier 子表：前者避免两套平行模型，Sprint 4/5 销售采购无需重构；代价是 3C-1 Customer 子模型暂未迁移（Sprint 5 统一处理）。
- BusinessPartnerRole 独立建模 vs 仅靠 BP.type 枚举：角色表支持无限扩展（LOGISTICS/OUTSOURCING 等），BP.type 保留兼容字段。
