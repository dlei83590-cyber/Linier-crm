# ADR-0005: Audit Center 升级（Sprint 3B）

- 状态：已接受
- 日期：2026-08-05
- 决策者：CIO + CTO 审核
- 分支：feature/sprint3-platform-capabilities

## 背景

Sprint 1 的 AuditLog 仅含 actorId/action/entityType/entityId/meta/ipAddress，
无法支撑安全审计、问题追踪（TraceId/RequestId）、数据回滚（Before/AfterData）、
终端环境（Device/Browser）与性能分析（Duration）。

Sprint 3B 第一优先级升级 Audit Center，使所有 CRUD 操作自动获得完整审计能力。

## 决策

### 1. 字段扩展（保留既有字段，避免破坏兼容）

| 新增字段 | 类型 | 说明 |
| --- | --- | --- |
| beforeData | Json? | 操作前数据快照（回滚/对比） |
| afterData | Json? | 操作后数据快照 |
| requestId | String? | 请求 ID（单请求追踪） |
| traceId | String? | 全链路追踪 ID |
| device | String? | mobile/desktop（UA 解析） |
| browser | String? | Chrome/Firefox/Edge/Safari（UA 解析） |
| duration | Int? | 操作耗时（毫秒） |
| result | AuditResult（SUCCESS/FAILURE/PARTIAL） | 操作结果 |

- `entityType`/`entityId` 即 ObjectType/ObjectId 语义，保留原名避免破坏既有 API。
- `ipAddress` 保留；`meta` 保留（通用扩展）。

### 2. requestMeta() 统一提取

- 新增 `requestMeta(request)` helper：一次提取 requestId/traceId/IP/Device/Browser。
- 所有写操作 API 调用 `requestMeta()` 传入 `writeAuditLog`，避免每个路由重复解析 UA/IP。

### 3. writeAuditLog 扩展

- 签名扩展为 `AuditLogParams`（新增 beforeData/afterData/requestId/traceId/device/browser/duration/result）。
- 既有调用点保持兼容（新字段可选）。

### 4. 审计查询 API

- `GET /api/audit-logs`：分页 + actorId/entityType/entityId/action/result/requestId/traceId/时间范围过滤。
- `GET /api/audit-logs/:id`：详情（含 Before/AfterData 与操作人）。
- 权限：`audit:view`（仅 SUPER_ADMIN/ADMIN 持有，MANAGER 不开放审计读权限——安全考虑）。

### 5. 迁移策略

- AuditLog 表已存在（0001），本迁移 **仅 ALTER 加列 + 建索引**，不重建表（CTO 规则：已上线迁移禁止修改）。
- 新迁移 `0005_audit_upgrade`：CREATE TYPE AuditResult + 8 列 + 3 索引（requestId/traceId/result）。

## 备选方案及放弃原因

- **重建 AuditLog 表**：破坏既有 23 处 writeAuditLog 调用点与历史数据 → 放弃。
- **独立审计事件表（Event Sourcing）**：与既有 AuditLog 并存会造成双写与查询混乱 → 放弃，后续事件总线（Domain Events）再评估。
- **全链路追踪接入 OpenTelemetry**：超出当前平台范围，先以 requestId/traceId 透传为主 → 后续演进。

## 影响

- AuditLog +8 列 + 1 枚举 + 3 索引；所有 CRUD 操作自动获得完整审计。
- 新增 audit-logs API（list/detail），权限 audit:view。
- requestMeta() 成为标准请求元数据入口。

## 对后续 Sprint 的影响

- Sprint 3B Menu/Dashboard/File API 全部复用 requestMeta + writeAuditLog 扩展。
- Sprint 4+ 业务模块 CRUD 自动获得 Before/AfterData 审计，无需额外开发。
- Domain Events（Sprint 4 前）可基于 auditLog 的 requestId/traceId 做链路关联。
